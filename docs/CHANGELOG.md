### Added

- **The exam bank scales by a grammar, not by typing** (`scripts/generate-exam-questions.mjs`, `src/content/generated-bank.ts`, `generated-bank-summary.txt`, `src/content/exam-bank.ts`). The bank was 35 hand-written items, which is enough to host an exam and not enough to host two rooms with different papers or to survive a host filtering by difficulty. The way out was not more typing but the observation that a question is a *shape*: a setup that establishes ground truth, a persona that decides the framing, and one SQL statement whose result the setup already predicts. `FAMILIES` are factories per topic — RLS probes per persona, privilege probes per role, MVCC visibility pairs, trigger effects, function call semantics, security audit reads — each emitting candidates with `setupSql`, `persona`, `answerSql` and an expectation stated as `expect.scalar` / `expect.errorIncludes` rather than as a hand-written `checks` array. **Ground truth is measured once, from the database, and never copied from the answer being tested**: `resolveExpect()` runs the expectation as the owner in its own transaction and converts it into a real `Check`, so the oracle and the reference answer are separate measurements of the same fact. `readScalarText()` reads the *wire* text, which is what the grader compares against — `sum(budget)` is the number `66000` in JavaScript and the string `"66000.00"` on the wire, and the first version of this script asserted the number and the first item written against the number graded wrong. Personas come from **parsing `src/lib/exam/personas.ts`** with `matchAll(/(\w+):\s*\{([^}]*)\}/g)` rather than from a list repeated here; a line-based parser mangled the single-line entries (`{name: 'owner'}`) and invented roles that do not exist, which is the same failure the exam's own setup had and the reason the file is read as blocks. Every candidate then passes **four gates** before it is emitted: (1) *dedupe* on `setupSql|persona|answerSql`, because the families overlap and a duplicate is a paper with a hole in it; (2) `grades` — the reference answer passes its own checks on real PGlite; (3) `notVacuous` — `SELECT 42` must fail, the same control the hand-written bank has been asserting since day one and the only test that rejects an oracle with no content; (4) `repeatable` — two runs agree, which is what catches the items that look fine and are not: `nextval`, `now()`, and anything whose setup leaks state through the shared session. **163 items shipped, 4 dropped, and every drop is named with the gate that killed it** — three duplicates and one `g-mvcc-4` whose oracle `SELECT 42` also passed. Two others were removed at authoring time with the reason written down: a `PREPARED STATEMENT` whose repeatability gate failed because ROLLBACK does not drop it in PGlite, and a `current_setting` prompt that throws for `anon` rather than returning the default. The bank is now **198 items across 7 topics (35 hand + 163 generated)**, assembled as `[...hand, ...generated]` per slug with `EXAM_BANK` flattened from it, so `/exam`'s count field reads 198 and the generator's output is a plain data file that `tsc`, vitest and the build all see. **The distribution is honest and lopsided**: RLS carries 110 of the 163 because it is the topic where a persona × privilege × expectation grid generates legitimately different questions, and indexes/MVCC carry 4 and 3 — those lessons' interesting facts are plan shapes and one-off measurements that do not survive being templated. `exam-bank.test.ts` runs its both-directions assertion over every item, hand-made or generated, so the generator cannot ship what a human would not have passed: **557 tests** now (3 skipped, the live e2e).

- **Exam — host a timed, visual SQL exam (`docs/SPEC-EXAM.md`, `src/lib/exam/`, `src/app/api/exam/`, `src/app/exam/`, `src/components/exam/`, `src/content/exam-bank.ts`).** A host sets the rules, gets a six-letter code, and distributes it; everyone who joins works **their own random paper**, and the host watches a leaderboard update while they do. Papers are **derived, not stored** — `mulberry32(seed)` + Fisher-Yates over a seed mixed from the exam's own and the participant's id, so two people at the same code get different questions, a reload gives the *same* different questions, and the server can re-derive any participant's paper without keeping one. **Every question is visual and executable**: a stimulus (a table, a set of statements, a heap diagram) plus a scenario built by real `setupSql` under a real persona, graded by the *same* `gradeChecks` the lesson cards and CI use — an answer cannot pass an exam while failing the lesson it came from. Isolation is a **transaction, not a fresh database**: Postgres DDL is transactional, so `BEGIN; setup; answer; ROLLBACK` undoes policies, grants, triggers and writes, which is the difference between grading 50 answers in seconds and needing 50 databases. `SET LOCAL ROLE` comes *after* setup, because setup is DDL and `lab_app_member` cannot alter what it does not own. The clock is **absolute and server-owned** (`startedAt + (i+1) * window`), never a client-side duration, so a reload cannot buy time and a tab opened late counts down from the same number; `advanceIfDue()` pulls state forward from the wall clock on any request instead of relying on a timer that outlives a handler. Answers arrive over polling `/state` with SSE as an enhancement, deliberately: the bundled docs scope the real-time limits to lambda hosts, and nothing in an exam may depend on an event arriving. **Three correctness hazards were closed before any UI existed** — `gradeChecks` reads `lastTable`, so setup and answer had to become separate `exec` calls or a no-table answer would be graded against setup's table and pass; one PGlite is one session, so concurrent submissions need a pool *and* a per-session promise-chain mutex (confirmed empirically by `PGlite is closed` under an un-awaited call); and a participant-issued `COMMIT` would end the grading transaction early and write into the **shared** database, so all transaction control is refused. The bank ships with a validator that **executes every item on real PGlite and rejects `SELECT 42`**, so a wrong oracle fails CI instead of awarding points in an exam; 30 items across 7 topics are live and every one of them is measured. Two pages, not the eight the spec first drafted: the eight screens are states of one `/state` frame, and one frame is what makes the host console and the participant view provably the same exam.

- **The playground runs with nothing listening: service worker, installable manifest, offline shell** (`public/sw.js`, `src/components/shell/ServiceWorkerRegister.tsx`, `src/app/offline/page.tsx`, `src/lib/pwa/offline.ts`, `src/lib/pwa/offline.test.ts`, `src/app/manifest.ts`, `src/app/icons/[name]/route.tsx`, `src/lib/site-meta.ts`, `next.config.ts`, `settings/`). - Four things had to be measured to get here, and three of them were bugs this branch shipped and then found. (1) **`cacheFirst` handed the live response to `cachePut`, which consumed the body**: the page still rendered, the cache held 1 entry of 16 MB, and the only evidence was the entry count. `res.clone()` before deciding, since the page is holding the only other copy. (2) **Monaco's chunks are unreadable by design.** They arrive through classic `<script>` tags, so the worker sees `type: 'opaque'` with `status: 0`, and filtering on `res.ok` silently refused to store 12 perfectly good 200s; the editor then needed a network while offline. `cacheable(res, isMonaco)` allows an opaque response *from that CDN only*, and the allowance is deliberately absent from the HTML path. (3) `/icon.svg` is fetched by the browser during the very first page load, which is the one load a freshly installed worker does not control, so offline it failed as a console error on every load; it now rides the precache. (4) Byte accounting is reported as **file counts only**, because all three sources for a size were tried: `Content-Length` was present on **1 of 31** entries (a compressed response stores none) and summed 6 MB against a real 17 MB, `blob().size` is exact for same-origin files (18.1 MB static, 0.75 MB pages) and structurally 0 for the opaque CDN entries, and `navigator.storage.estimate().usageDetails.caches` charged **132 MB** for a copy whose entries sum under 23 MB while continuing to report freed bytes for minutes after an erase (deletion is deferred, which is also why a cleared card must not print a size at all). `/settings` therefore says `77 files` with `39 / 25 / 13` per cache and no number nobody stands behind.

Icons are an `ImageResponse` route (`src/app/icons/[name]/route.tsx`) that draws the same composition as `app/icon.svg`, prerendered for the three manifest names, with the mark at 0.72 scale for the plain icons and 0.56 for the maskable one so it stays inside the 60 % safe zone; the maskable background is `APP_BG` from `src/lib/site.ts`, the same constant as `manifest.ts`'s `background_color`, so the splash matches. - **One motion layer for the whole app** (`src/lib/motion.ts`, `src/app/template.tsx`, 13 call sites). Page changes, popup opens, section swaps and the assistant sheet were each tuned by hand, so nothing moved at the same speed or with the same easing, and one of them (the playground assistant's slide-in) never answered `prefers-reduced-motion` at all. `src/lib/motion.ts` is now the only vocabulary: `pageIn`, `dialog.backdrop` / `dialog.panel`, `popover(offset)`, `sheet`, `swap`, `tabSwap`, `fade`, `listItem(i)`, plus `STILL` and one hook, `useMotionPresets()`, that resolves every preset against `useReducedMotion()` so a reader who asks for less movement gets the same product with nothing animating. Two things this layer had to learn by measurement. (1) **The hook hands back finished props, not factories**: `const { popover: menu } = useMotionPresets()` followed by `{...menu}` spreads a *function*, which React accepts without a word and renders as no animation whatsoever. - **The "On this page" rail knows where the reader is, and scrolling there is now a glide instead of a teleport** (`src/components/learn/OnThisPage.tsx`, `src/app/globals.css`). The spy was an `IntersectionObserver` with `rootMargin: '-72px 0px -70% 0px'`, which is the idiomatic tool and the wrong one here: the observer only reports headings whose intersection *changed* in a batch, so a **jump** — a TOC click, a `#hash` on load, a scroll to the end of an 8,000 px lesson — can settle without the section now in view ever appearing in that batch, and the highlight stays wherever it happened to be last. It is now direct arithmetic on `getBoundingClientRect().top + scrollY`, once per animation frame at worst, over a `FOLD` of 96 px. That number is load-bearing and its neighbour is the reason: `globals.css` sets `scroll-margin-top: 5rem` (80 px) so a clicked heading parks below the sticky header, and a `FOLD` of 72 put the line *above* where the browser parks the heading — the click and the spy were two authorities disagreeing by exactly one section, which is what the flicker was. Three more facts the observer could not express: reaching the bottom is its own answer (the last section of a lesson can be shorter than the viewport, so its heading never crosses the line even at maximum scroll — measured on the RLS lesson, where the end of the page lit "Performance tips" while the reader was at "Check yourself"); above the first heading nothing is current, rather than the first item being; and `offsetTop` is measured against the nearest *positioned* ancestor, so it silently disagrees with `scrollY` the moment any wrapper becomes positioned — a rect is document truth by construction. **A click now owns the marker until scrolling settles**: during an animated jump the sections being flown over are not where the reader is going, so the geometry would light up wrong sections for the whole glide and land wrong at the end. Deliberately *not* `preventDefault` + `scrollIntoView` — the native anchor is what updates the hash (a link to this exact moment stays copyable) and moves focus, and `scroll-behavior: smooth` on `html` does the gliding; the click just sets a lock. The unlock is `scrollend`, not a debounce on `scroll`: a debounce needs a quiet window longer than the gap between scroll events, and that gap measured **250 ms** here (a throttled ~4 Hz frame budget), so any window short enough to feel instant unlocks mid-flight and any window safe enough leaves the marker stale. `scrollend` is the browser stating the scroll is over at any frame rate; an 800 ms re-arm on every scroll event is the backstop for the one case that emits neither, which is clicking the section you are already on — without it the spy stays dead for the rest of the lesson. `scroll-behavior` is scoped to `prefers-reduced-motion: no-preference` with an explicit `auto` in the reduce block, because the global kill-switch at the bottom of the file zeroes transition and animation *durations* and cannot reach scroll behaviour at all, and it does not inherit, so the sidebar's own scrolling stays under explicit control. That last part matters because **the rail scrolls itself now**: it is a sticky `overflow-y-auto` column, so on a long lesson the current section slid out of the rail while the page scrolled fine — a live indicator nobody could read. `scrollIntoView` is the wrong tool because it walks every scrollable ancestor *including the window* and fights the scroll the click just started, so the effect adjusts the one container's `scrollTop`; the container is found by walking up until `overflowY` actually clips, because the `<ul>` itself measures `overflow-y: visible` and `scrollTo` on it is a silent no-op. The nudge fires only when the row is genuinely outside, and only as far as needed — a rail that recentres on every section swims during a read.
